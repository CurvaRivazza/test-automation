# Тестовое задание: Автоматизация тестирования

## Запуск тестов

### 1. Запустите тестируемое приложение:
```bash
java -jar -Dsecret=qazWSXedc -Dmock=http://localhost:8888/ internal-0.0.1-SNAPSHOT.jar
```
### 2. Запустите тесты:
```bash
mvn clean test
```

### 3. Сгенерируйте отчет Allure:
```bash
mvn allure:serve
```

## Реализация работы с WireMock

### Конфигурация WireMock в проекте

В проекте реализована работа с WireMock через класс `WireMockBase`, который запускает мок-сервер на порту 8888. Все тестовые классы (`AuthTest`, `ActionTest`, `LogoutTest`) наследуются от этого базового класса, что обеспечивает единую конфигурацию мок-сервисов.

### Методы для работы с WireMock

Каждый тест автоматически настраивает стандартные ответы от внешних сервисов. Вот основные методы, реализованные в `WireMockBase`:

**Настройка ответов:**
- `setupExternalAuthSuccess()` — настраивает успешный ответ (200 OK) от внешнего сервиса авторизации `/auth`
- `setupExternalActionSuccess()` — настраивает успешный ответ (200 OK) от внешнего сервиса действий `/doAction`
- `setupExternalServiceFailure(endpoint)` — имитирует сбой внешнего сервиса (ответ 500) для указанного эндпоинта
- `setupExternalServiceTimeout(endpoint)` — имитирует медленный ответ внешнего сервиса (задержка 5 секунд)

**Проверка взаимодействия:**
- `verifyExternalAuthCalled(token)` — проверяет, что внешний сервис авторизации `/auth` был вызван с указанным токеном
- `verifyExternalActionCalled(token)` — проверяет, что внешний сервис действий `/doAction` был вызван с указанным токеном

### Использование

WireMock используется во всех тестах, где необходимо взаимодействие с внешними сервисами:

1. **Тесты авторизации (AuthTest)** — мокируется вызов `/auth` для проверки успешной и неуспешной аутентификации
2. **Тесты выполнения действий (ActionTest)** — мокируется вызов `/doAction` для проверки возможности выполнять действия после авторизации
3. **Тесты выхода из системы (LogoutTest)** — мокируется вызов `/auth` при предварительной авторизации перед logout

## Обнаруженная особенность
В документации указано, что токен должен состоять из символов A-Z0-9, но фактически приложение принимает только ограниченный набор символов A-F0-9.
